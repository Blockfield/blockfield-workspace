# Blockfield workspace

Клиентская и серверная сборки, исходники модов и инструменты локального стенда Blockfield.

## Подготовка

### Клонирование

```sh
git clone --recurse-submodules https://github.com/Blockfield/blockfield-workspace.git
cd blockfield-workspace
```

Для приватных submodules нужен доступ к организации Blockfield.
[Подробная настройка](docs/DEVELOPING.md).

Отдельные облачные стенды для параллельных задач:
[boat.dev](docs/BOAT.md), CLI через `just boat` без глобальной установки.

### Зависимости

- Git.
- Just 1.57.0.
- Python 3.12+.
- GitHub CLI с доступом к Blockfield.
- Node.js 22 для проверок документации и web-кода.

Поддерживаются Linux и Windows, без mise, WSL и Docker.
Зависимости проверок устанавливаются в кеш и venv проекта. Полный JDK 21
скачивается автоматически в `.dev/jdk/` при первой Java-команде; системная Java
и `JAVA_HOME` не нужны. `BF_DEV_HOME` переносит также этот JDK в свой стенд.
[Ресурсы R2](docs/ASSETS.md) скачиваются по публичному HTTPS; ключ R2 для setup не нужен.

## Запуск

Перед запуском проверьте владельцев занятых портов; используйте только свой стенд.

```sh
just status
just check
just setup
just server start
just play --server 127.0.0.1:25599
```

`just setup` подготавливает JDK, сервер, клиентский пак, Minecraft assets/libraries/natives,
portablemc; игровые процессы не запускаются. Testbot устанавливается только с
`just setup --testbot` (сборка из исходников) или `just setup --testbot <jar>`.
Carpet устанавливается автоматически только в сервер тестового стенда;
в клиент и опубликованные клиентский/серверный паки он не входит.
Обычный `just play` использует выбранную при setup комплектацию и ждёт готовности
рендера клиента, показывая спиннер; создание JVM ещё не означает готовность игры.
Повторная команда достраивает
недостающие части. `--force` обновляет runtime, сохраняя мир, карты и пользовательские
options/logs/screenshots клиента. Исходники модов собираются отдельно через `just build-mods`.
Стенд хранится в `.dev/`. Остановка: `just play --stop` и `just server stop`.
Форматирование исходников: `just format`.
CI выполняет обычные проверки на GitHub-hosted Linux; headless-пробу и Windows
проверяйте локально.

## Hot reload (HMR)

Для Java-кода `localmods/blockfield-mod` включите JDWP на своём остановленном
стенде и запустите watcher:

```sh
just status
just build-mods blockfield-mod
just setup --force
just server start --debug
just play --mod --debug
just watch both
```

`just watch both` следит за сервером, клиентом и общим Java-кодом; сборки
нужных сторон выполняются последовательно до первого обновления runtime.
`just watch server` и `just watch client` оставляют только выбранную сторону.
Используйте один watcher за раз. Изменения тел методов применяются без
перезапуска; новые и удалённые классы, миксины и несовместимые изменения требуют
перезапуска соответствующего своего процесса.

Для одной итерации после сохранения Java-кода используйте `just iterate both`
(то же, что `just watch both --once`). Запись в `BF_DEV_HOME/watch-receipt.json`
позволяет пропустить неизменившуюся сторону после проверки собственного процесса,
содержимого исходников и установленного JAR. Общие Java-правки собирают обе стороны.
Ресурсы и зависимости требуют полного цикла на остановленном стенде.
[Область HMR, ограничения и полный цикл](docs/DEVELOPING.md#hot-reload-hmr).

## Короткая игровая проверка

На своём изолированном клиенте с testbot запишите кадры и действия одним вызовом:

```sh
just capture --seconds 3 --fps 5 --video --actions actions.json
```

`actions.json` содержит массив `{at, tool, arguments}` с разрешёнными игровыми
MCP-инструментами. Результат — PNG, manifest с фактическими временами и MP4;
запись не наблюдает desktop. [Формат действий и MCP](docs/DEVELOPING.md#mcp).
Агенту требуется согласие на текущую проверку этого изолированного клиента.
Linux использует свой Xvfb; Windows x64 — отдельные неинтерактивные window station
и desktop с software Mesa. На отдельном собственном `BF_DEV_HOME` команда
`just play --headless --probe --released-pack` автоматически проверяет меню,
рендер, ввод, capture и restart полного опубликованного клиента Blockfield
`v2.63.0`. Архив доступен публично и закреплён по checksum; доступ к приватным
репозиториям не нужен. Без `--released-pack` проверяются базовые
Minecraft/Fabric/testbot. Probe завершает собственные процессы; серверные
и боевые сценарии с несколькими клиентами требуют отдельной приёмки.

## Структура

| Каталог                         | Содержимое                                                  |
| ------------------------------- | ----------------------------------------------------------- |
| `client/`, `server/`            | Клиентский и серверный паки                                 |
| `localmods/`                    | Игровой мод, декор, музыка, форки и рецепты патчей          |
| `scripts/`, `bf.py`, `justfile` | Инструменты разработки и проверки                           |
| `docs/`                         | Инструкции и результаты аудита                              |
| `.dev/`, `temp/`                | Локальные игровые экземпляры и диагностика; не входят в Git |

Клиент, сервер и 15 каталогов `localmods/` — отдельные репозитории,
закреплённые как submodules. Правьте и коммитьте код в его репозитории;
workspace фиксирует проверенные SHA.

## Названия и бренд

- Название и логотип Blockfield используются в собственных продуктах: игре,
  лаунчере, сайте и клиентских дистрибутивах. В их README достаточно одного
  логотипа и ссылок на запуск или загрузку.
- Форки сохраняют название, логотип и авторство исходного проекта. В README
  указываются источник, наши изменения и порядок сборки; Blockfield обозначает
  сопровождающую команду, а не автора исходного мода.
- Патчи и зеркала сторонних ресурсов называются по исходному проекту. Наш знак
  и общая лицензия Blockfield не должны обозначать права на чужие ресурсы.
- Внутренним инструментам достаточно названия и описания задачи. Рекламные
  шапки, повторяющиеся слоганы и бейджи со статичными версиями не нужны.
- Брендирование пользовательских экранов сайта, лаунчера и игры помогает
  узнать сервис. Технические ID, пакеты, namespace и имена артефактов меняются
  только по технической необходимости, с учётом совместимости и лицензий.
