# Ресурсы в Cloudflare R2

Bucket `blockfield-assets` хранит опубликованные входы сборок. Чтение публичное
через **https://assets.blockfield.pro**, запись — только по ограниченному R2-токену.
Отдельный приватный бакет предназначен для резервных копий (имя не публикуется);
его доступ не меняется.

| Ресурс          | Ключ объекта                                               |
| --------------- | ---------------------------------------------------------- |
| Схемы WorldEdit | `schematics/v1/blockfield-schematics.zip`                  |
| Музыка          | `music/music-v3/blockfield-music-3.jar`                    |
| Ганпак          | `gucci-vuitton-attachment/v1/gucci-vuitton-attachment.zip` |
| Миры и карты    | `world-seed/world-seed-v<N>/world-seed.zip`                |
| Пакеты карт     | `maps/<map-id>/<map-release>/<map-id>.zip`                 |

Все опубликованные игровые ресурсы, включая прежние версии, скопированы в R2:
10 world-seed, 3 отдельных пакета карт, 3 музыкальных JAR, архив схем и ганпак.
18 уникальных бинарных артефактов занимают 792 457 398 байт. Реестр ключей,
размеров, SHA256 и исходных релизов — [assets-manifest.json](assets-manifest.json).
Вместе с описаниями, checksum и снимками исходных GitHub-метаданных это
73 объекта, 792 576 109 байт.
Совпадающая музыка v3 из двух репозиториев хранится одним объектом с двумя
записями происхождения. JAR игровых модов, инструменты и готовые дистрибутивы
остаются артефактами GitHub; редактируемые исходники ресурсов остаются в Git.

GitHub Releases сохраняют теги, описания и checksum как историю публикаций.
После проверки переноса три исходных ZIP/JAR удалены из вложений GitHub;
их неизменённые байты и копии метаданных сохранены в R2. Освобождено
84 915 639 байт; оставшиеся описания и checksum занимают 5 597 байт.
После стандартизации удалены также три проверенных дубликата world-seed v8–v10
из активного серверного репозитория: ещё 184 477 593 байта. Их теги и исходные
описания сохранены, добавлены вложения `release-notes.md` и `SHA256SUMS`.
Всего удалённые бинарные вложения освобождают 269 393 232 байта до учёта
маленьких добавленных метаданных.
С учётом 3 026 байт новых GitHub-метаданных чистое освобождение —
269 390 206 байт (269,39 МБ).
Эти файлы уже хранились вне Git: перенос не уменьшает размер клонов.
Архивный модпак прежней организации сохранён без изменений: прежние версии
доступны в R2, а оригинальные архивные вложения остаются резервной копией.

## Чтение для сборок и локального стенда

`just setup` не требует R2 credentials. Клиент и сервер преобразуют логический
`r2-url` вида `s3://blockfield-assets/<ключ>` в
`https://assets.blockfield.pro/<ключ>` и скачивают через HTTPS без авторизации.
Bucket, путь и закреплённый checksum проверяются; ошибку HTTP или SHA256
не заменяют скачиванием из другого источника. URL исходного GitHub Release
сохраняется для происхождения. Доступ gh по-прежнему нужен для приватных JAR
и исходников. Ключи чтения не нужно выдавать разработчикам или хранить в Git.

Публичный домен подключён непосредственно к R2 в Cloudflare, а не к Dokploy.
Cloudflare создаёт отдельную DNS-запись `assets.blockfield.pro`; wildcard
остальных поддоменов сохраняется. Для изменения домена обновите
`PUBLIC_R2_BASE_URL` в обоих fetchers и эту документацию.

## Доступ для публикации без браузера

`just rclone` запускает rclone 1.74.3 из кеша workspace: версия и SHA256
архивов для Linux/Windows amd64/arm64 закреплены в `scripts/toolchain.py`.
Архивы инструмента скачиваются из официального GitHub Release rclone;
их SHA256 совпадают с исходными архивами `downloads.rclone.org`.
Глобальная установка не нужна.

Локальный rclone-конфиг хранится вне Git с правами `0600` на Linux. Точный путь
к нему — в приватных заметках издателя; ниже он показан как `<R2_CONFIG>`.
Для CLI используйте `--config`. Конфиг содержит два remote:

```ini
[r2_read]
type = s3
provider = Cloudflare
access_key_id = <Access Key ID токена на чтение>
secret_access_key = <Secret Access Key токена на чтение>
endpoint = https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com
region = auto
no_check_bucket = true

[r2_upload]
type = s3
provider = Cloudflare
access_key_id = <Access Key ID токена на запись>
secret_access_key = <Secret Access Key токена на запись>
endpoint = https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com
region = auto
no_check_bucket = true
```

Оба токена ограничены только `blockfield-assets`. Их значения не печатают,
не передают аргументами команд и не коммитят. Проверка доступа:

```sh
just rclone --config <R2_CONFIG> lsf r2_read:blockfield-assets --recursive
```

Сборочные workflow клиента/сервера используют публичный HTTPS и не передают
R2 credentials. Конфиг выше нужен издателю для загрузки и проверки через S3;
токен записи в сборочные workflow не передаётся.

## Публикация новой версии

Архивы собираются каноническим Python/zlib соответствующего рецепта. Смена
хранилища не является поводом пересобирать исторический артефакт или менять
его опубликованный checksum.

Подготовьте отдельный каталог с артефактом и `release-notes.md`.
Единая команда из workspace создаёт `SHA256SUMS`, если его нет, проверяет
существующий checksum, загружает новый version prefix и проверяет его скачиванием:

```sh
just assets schematics/v2 <каталог-релиза>
just assets music/music-v4 <каталог-релиза>
just assets world-seed/world-seed-v11 <каталог-релиза>
```

Команда использует `server/scripts/publish-assets.py` и закреплённый rclone.
`copy --immutable --checksum` не удаляет другие объекты и запрещает замену
отличающихся файлов. `check --download --one-way` сравнивает содержимое всех
публикуемых файлов, сохраняя дополнительные исторические метаданные в prefix.
При ошибке проверки пины не обновляют. Не используйте `sync`, `purge`,
`delete` или `--ignore-existing` для опубликованных версий.
После успешной проверки опубликуйте в GitHub Release только описание,
`release-notes.md` и `SHA256SUMS`. ZIP/JAR ресурсов туда не загружайте.
Музыкальный рецепт теперь только собирает JAR; публикация выполняется этой
общей командой. Прежний флаг `--no-publish` оставлен для совместимости.

В `resources.lock.json`, `distribution/assets.lock.json`,
`distribution/maps.lock.json` клиента/сервера или `[download]` metafile музыки
обновите `r2-url` (`s3://blockfield-assets/<ключ>`) и закреплённый hash.
`url` сохраняет ссылку на исходный GitHub Release для происхождения и
release notes. При наличии `r2-url` сборка скачивает только из R2 по публичному HTTPS, проверяя
прежний hash; автоматического отката на GitHub нет. Для музыки пересчитайте
hash её metafile в `index.toml`, затем hash индекса в `pack.toml`.
У map-пина поля `repository`, `release` и `asset` сохраняют происхождение;
`r2-url` указывает на `maps/<map-id>/<release>/<asset>`. Новые принятые карты
публикует `server/scripts/maps/publish_map.py`: тот же R2 publisher, GitHub
метаданные и PR с согласованными JSON/пином; публикация карты не развёртывает прод.
Для world-seed CI и локальный стенд используют `scripts/fetch-world-seed.py`:
кеш проверяется по SHA256, новый файл заменяет старый только после проверки.
При добавлении версии внесите её ключ, размер, SHA256 и происхождение в реестр.

Игроки скачивают готовые файлы с раздачи Blockfield, им не нужны R2 credentials.
Переезд тех же байтов не меняет игровой digest или контракт совместимости.
Теги клиента/сервера и прод-деплой требуют отдельного подтверждения владельца.

## Игровая проверка переноса — 2026-09-30

Чистые клиентский и серверный паки получили ресурсы из R2. Клиентский digest
остался `a5a16b9b3a6509393221b815938df6dbb1f8b919960944e55934263440547371`,
общий контракт — `cc87fa37b249a95fe6b0e52c9d4db52d2d1c4226e42459f158b51aa28d919965`.
На отдельном локальном сервере в профиле `test` и клиенте с виртуальным экраном
проверены загрузка саундтрека (38 треков/15 состояний) и воспроизведение треков хаба,
загрузка ганпака и отображение прицела HCO с его характеристиками,
загрузка всех пяти перенесённых схем WorldEdit. Вставка BlueLobby изменила
626 блоков. Музыкальный JAR, пять схем и 504 файла ганпака совпадают
побайтно с исходными вложениями GitHub; все восемь объектов R2 проверены по SHA256.

Предупреждения WorldEdit о замене блоков воздухом относятся к старым клиентским
`Kozlik.schem` и `Kozlik2.schem`: в них остались исходные ID декора `railways`,
дверей `manyideas_doors` и мебели `cozy_home`. Игровые карты доставляются отдельно,
через опубликованный `world-seed-v10`. Проверка его SHA256 и палитр Kozyatyn,
Berdichev, Zaliznichne и Konstaxa подтвердила сохранённые замены на `blockfield:`,
`cozyhome:` и ванильные блоки. Широкие пути `railways:track_create_andesite_wide`
и `railways:track_dark_oak_wide` поддерживаются закреплённым портом Create.
Исправления карт опубликованы; устарели именно две вспомогательные схемы.
При переносе в R2 архив схем сохранён побайтно и не пересобирался.
Проверка не меняла прод и не выпускала клиентский/серверный релиз.

## Проверка единого хранилища — 2026-09-30

Все 18 уникальных ресурсных артефактов и их метаданные проверены скачиванием
из R2; прежние SHA256 сохранены. Каждая версия содержит описание и checksum.
Свежие world-seed v10 и пакет firing_range получены из R2 в отдельном пустом
кеше. Клиентская и серверная сборки прошли с прежним digest и контрактом;
все четыре ZIP/MRPACK побайтно совпали с результатом предыдущей игровой проверки.
Нового игрового запуска для смены хранилища не выполнялось. Музыка, ганпак и
схемы проверялись в игре выше; у всех ресурсов сохранены исходные байты.
Изменения в main и публикация ресурсов в R2 не означают новый игровой релиз
или прод-деплой.

На GitHub runner загрузка world-seed и пакета карты из R2 прошла; клиентская
сборка и проверки кода также прошли. Полный серверный CI останавливается
на несовместимости с закреплённым опубликованным клиентским манифестом:
тот же отказ был [до переноса карт](<private-submodule>/actions/runs/36706595853)
и остался [после него](<private-submodule>/actions/runs/36714042784).
Проверка совместимости сохранена. Локальные сборки выше использовали
манифест согласованного текущего клиента, без выпуска или прод-деплоя.
