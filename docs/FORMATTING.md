# Формат исходников Blockfield

Все активные репозитории Blockfield содержат собственные `.editorconfig` и
`.gitattributes`: настройки работают и при отдельном клонировании, без workspace.
Редактор должен поддерживать EditorConfig; если поддержки нет из коробки,
включите соответствующее расширение. Итоговый формат задаёт закреплённый formatter.

| Файлы                                                             | Окончания строк                                         | Отступы                             |
| ----------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------- |
| Python, Java, Kotlin, Rust, shell и остальные текстовые исходники | LF                                                      | 4 пробела                           |
| JSON/JSONC, YAML, Markdown, JS/TS, CSS/SCSS/Less, HTML/SVG, Astro | LF                                                      | 2 пробела                           |
| Go                                                                | LF                                                      | Табы; `gofmt`, ширина отображения 8 |
| Makefile, `*.mk`, `.gitmodules`, `.gitconfig`                     | LF                                                      | Табы, ширина отображения 4          |
| Windows `*.bat`, `*.cmd`                                          | CRLF в Git и в рабочей копии, без конвертации (`-text`) | 4 пробела                           |

Текст сохраняется в UTF-8 с завершающим переводом строки. Пробелы в конце строк
удаляются, кроме Markdown: два пробела могут обозначать перенос строки.
Бинарные ресурсы исключены из нормализации Git. Git никогда не переписывает
байты: каждый путь покрыт `.gitattributes`, поэтому локальные значения
`core.autocrlf` ни на что не влияют; менять глобальный Git config разработчика
не требуется. Застарелая рабочая копия лечится через `git add --renormalize .`
и проверку `git status` (или свежим клоном). Ruff явно пишет LF на обеих ОС; `rustfmt.toml`
лаунчера закрепляет Unix-переводы строк для Rust.

## Применение и проверка

В workspace, клиенте, сервере, лаунчере, proxy, workshop и репозиториях модов:

```sh
just format
just format-check
just lint
```

Java мода дополнительно проверяется через `just java-check` из
`localmods/blockfield-mod`; команда запускает Gradle, поэтому сначала проверьте
`just status` из workspace и соблюдайте лимиты сборки.

В сайте и errors используйте `pnpm format` и `pnpm format:check`.
В боте — `gofmt -w .` и `gofmt -l .`; последняя команда должна дать пустой вывод.
CI запускает те же закреплённые проверки на Linux и Windows.

`format-check` также проверяет, что Git не конвертирует окончания строк:
`git ls-files --eol` не показывает `i/crlf`/`i/mixed` нигде, кроме записей
`*.bat`/`*.cmd` с атрибутом `-text` (они хранят CRLF побайтово), а каждый
`*.bat`/`*.cmd` обязан иметь `-text`; при сбое выполните
`git add --renormalize .`.

Форматтеры обрабатывают исходники и документацию в своей существующей области.
Игровые конфиги, resource/data packs, миры, кеши, generated/build outputs и
исторические артефакты не следует массово переформатировать: изменение их байтов
может менять checksum, pack index и контракт. Новые правила редактора не заменяют
проверку этих изменений при подготовке релиза.
